# Lumora 核心规范 — 打破常规

> 只为 AI 生图创作者而做。不是更好看的图库，是另一种图库。

## 我们为谁而做

Lumora 只服务 AI 生图创作者（Stable Diffusion / ComfyUI / Flux 用户）。
普通用户图库的功能——手机照片、人脸识别、相册分享、EXIF 编辑、云同步——
不在产品里。判断一个功能去留的唯一标准：它是否服务于
「生成 → 筛选 → 组织 → 复用」的创作流。

## 打破常规

### 铁律一：拒绝常规形态

Eagle / Lightroom / Adobe Bridge 里有的功能形态，Lumora 只做**不同的做法**，
不做「更好的版本」。

- 禁止文件夹树式管理
- 禁止把收藏做成目录层级
- 禁止把 AI 做成按钮
- 禁止「输入框 + 结果列表」式搜索

### 铁律二：AI 是主语，不是插件

创作者最自然的表达是「一句话 / 一张图 / 一组参数」，不是点菜单。

- 搜索 = 联想
- 组织 = 自动策展
- 理解 = 随时可问
- 每个管理功能都必须能回答「为什么这张图在这里」

### 铁律三：语义是图片的第一身份

一张图的本质是向量 + 记忆（提示词、模型、seed、变体关系），
不是路径、标签或文件夹。相册、收藏、去重、导出全部建立在语义层之上；
标签只是语义的投影，不是本体。

## 立项四问

每个功能开工前必须全部通过：

1. 普通用户图库也有这个功能？→ 不做，或重做成创作者版本。
2. Eagle / Lightroom 也有这个功能形态？→ 重想做法，直到不同。
3. 创作者最自然的表达是点菜单，还是给一句话 / 一张图 / 一组参数？→ 优先后者。
4. 把 AI 从功能里拿掉，它还成立？→ 若成立，只是常规功能的包装，重想。

## 边界

- 破常规的：产品形态、交互范式、数据组织。
- 不破的：代码约定（CLAUDE.md Rule 11）、质量门禁、可学习性底线。

*此规范是唯一权威；DESIGN.md 的视觉方向与 CLAUDE.md 的规则均服从于它。*
