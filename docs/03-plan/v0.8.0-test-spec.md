## 1. test_spec — 测试规范

### 1.1 目标

以可追溯、可重复、可自动化的方式验证 v0.8.0 全部功能，守住版本质量门禁：
**≥ 475 测试 | TypeScript 0 错误 | 100% 通过率**（当前实测 605 / 0 / 100%）。

### 1.2 测试层次

| 层次 | 工具 | 位置约定 | 负责内容 |
|------|------|----------|----------|
| 类型检查 | `tsc --noEmit` | 全仓 | 编译期契约、类型安全、未使用告警 |
| Store 单元测试 | vitest | `src/stores/__tests__/` | 状态变更、异步动作、错误处理、依赖注入行为 |
| API 单元测试 | vitest | `src/lib/api/__tests__/` | IPC 参数、返回转换、缓存、写命令语义 |
| Hook 单元测试 | vitest + RTL | `src/hooks/__tests__/` | 生命周期、事件监听、重试/退避、乐观更新 |
| 组件测试 | vitest + RTL + jsdom | `src/components/**/__tests__/` | 渲染、交互、边界条件、无障碍、设计合规 |
| 页面/集成测试 | vitest + RTL | `src/features/**/__tests__/` | 路由集成、跨组件数据流 |
| Rust 后端测试 | `cargo test --lib` | `src-tauri/src/**` 内联 `mod tests` | SQL 拼接、格式转换、重命名、导入去重、迁移幂等 |
| 构建验证 | `npm run build` | - | 生产构建成功 + 产物预算 |

### 1.3 命令

```bash
npx tsc --noEmit                    # 类型门禁
npx vitest run                      # 前端全量（退出码 0 且 100% 通过）
cd src-tauri && cargo test --lib    # Rust 全量
npm run build                       # 生产构建
node scripts/perf-budget.mjs        # 产物预算校验
```

### 1.4 命名与组织约定

- 测试文件与被测文件同目录 `__tests__/` 下，命名 `<module>.test.ts(x)`。
- `describe` 按被测单元分组，`it` 描述行为而非实现（如 `renders CFG scale`、`rolls back on API failure`）。
- 外部依赖一律 `vi.mock`；store 使用 `createXStore(mockDeps)` 注入而非依赖真实 API。
- Rust 测试使用临时目录/内存 SQLite，禁止触碰真实用户数据。

### 1.5 开发流程

每个 WBS 条目遵循 **RED → GREEN → REFACTOR**：先写失败用例，再实现到通过，最后按既有模式重构；提交前必须跑完 1.3 全部命令。

## 5. constraints — 约束条件

### 5.1 环境约束

- **无网络**：所有自动化测试禁止访问外部服务；Ollama/CLIP 相关代码一律 mock。
- **无 GUI**：前端测试运行于 jsdom，不启动 Tauri 窗口；后端测试用临时目录 SQLite。
- **平台**：sidecar（clip_server.py）仅在 Windows 上人工验证，CI 不运行 Python 依赖。
- **沙箱**：vitest/vite 需要读取工作区上级目录，CI 构建机需放开该权限（本地开发已确认可行）。

### 5.2 质量约束

- 提交门禁：`tsc --noEmit` 0 错误、`vitest run` 退出码 0 且 100% 通过、`cargo test --lib` 全绿、`npm run build` 成功。
- 测试数量 ≥ 475（当前 652 + 123）。
- 禁止删除既有测试而未提供等价替代（`a50bd1f` 中已恢复 imageStore / useImageActions / FavoritesPage 测试）。

### 5.3 设计约束

- 组件必须通过 `design-compliance.test.ts`（16 条：禁 Inter、禁星星/红心、禁 pill、禁毛玻璃、禁紫色渐变等）。
- 弹窗/横幅必须提供 role 与 aria 属性（`accessibility.test.ts` 12 条）。
- 文案必须走 i18n JSON（zh/en），`t(key, lang?, params?)` 签名，禁止硬编码中文。

### 5.4 性能约束

- 构建产物受 `scripts/perf-budget.mjs` 预算约束（改动引入超预算 chunk 需先行说明）。
- 图片渲染保持懒加载/无限滚动路径，不得引入全量图片同步渲染。

### 5.5 代码约束

- 遵循 `CLAUDE.md`：最小改动、不引入新模式、先读架构文档、测试必须验证真实需求。
- store 统一使用依赖注入工厂（`createXStore(deps)` + 预接线 `useXStore`），新 store 不得直接耦合 API 模块。

### 5.6 CI 约束（补齐项）

- CI 必须跑 `tsc --noEmit`、`vitest run`、`npm run build`、`cargo test --lib`、`cargo check`（现已在 ci.yml）。
- CI 补跑 `node scripts/perf-budget.mjs`（当前缺失）；建议增加 `cargo clippy -- -D warnings` 与 `cargo fmt --check`。
- 建议增加覆盖率门禁（`vitest run --coverage`），首次基线以现有 605 用例为准。

### 5.7 稳定性约束

- 定时器/异步一律使用 `vi.useFakeTimers` + `act`，禁止依赖真实 sleep；测试不得访问网络或外部服务。
- 用例必须幂等、顺序无关（避免跨用例共享 store 单例状态未重置）；`beforeEach` 重置 store 状态。
- 禁止断言真实时间、随机值或未经 mock 的本地环境差异。

### 5.8 安全约束

- 后端筛选/搜索一律参数化查询（现状符合），禁止拼接用户输入进 SQL。
- 重命名/转换/导出模板必须处理路径穿越（`..`）、绝对路径与 Windows 保留字符。
- 拖拽/导入路径校验：只接受图片扩展名 + 文件夹两种形态，禁止目录遍历写入。

### 5.9 i18n 一致性约束

- zh/en JSON 键集合必须一致（当前基线 375=375），新增 key 两文件同步提交。
- 禁止硬编码展示文案（已发现 ConvertDialog "file/files" 违反，GA-05）。
- 参数替换必须走 `t(key, lang?, params)` 签名，禁止手写字符串拼接。
