# superpowers 完整工作流 — Workflow 设计

## 整体流程

```
用户提需求
  │
  ▼
┌─ 阶段 1: 脑暴 (ASKUSER 闸门) ──────────────────┐
│  • 探索上下文                                     │
│  • 逐个 question 确认                             │
│  • 写设计文档 → 用户批准                          │
│  • ASKUSER: "设计批准，是否进入规划？"          │
└──────────────────────────────────────────────────┘
  │
  ▼
┌─ 阶段 2: 切 /plan 模式 (机械闸门) ─────────────┐
│  • 用户手动切 /plan — Write/Bash 被禁用          │
│  • 加载 writing-plans skill                       │
│  • 写正式分步计划文件                              │
│  • ASKUSER: "计划批准，是否切 /auto 实现？"    │
└──────────────────────────────────────────────────┘
  │
  ▼
┌─ 阶段 3: 实现 (workflow 编排) ──────────────────┐
│  • 用户切 /auto                                  │
│  • 运行 workflow: superpowers-implement           │
│    ├─ 按计划步骤派子 agent 执行                   │
│    ├─ 每步独立实现 + 测试                         │
│    └─ 全部完成后通知用户                          │
└──────────────────────────────────────────────────┘
  │
  ▼
┌─ 阶段 4: 验证 (workflow 编排) ──────────────────┐
│  • 运行 workflow: superpowers-verify              │
│    ├─ 加载 verification-before-completion skill   │
│    ├─ cargo check (Rust)                          │
│    ├─ vitest run (前端)                            │
│    ├─ 检查 git diff                               │
│    └─ 输出验证报告                                │
└──────────────────────────────────────────────────┘
  │
  ▼
┌─ 阶段 5: 收尾 (ASKUSER 闸门) ──────────────────┐
│  • ASKUSER: "合并到 main / 提 PR / 继续开发？" │
│  • 执行用户选择                                   │
└──────────────────────────────────────────────────┘
```

## Workflow 拆分

实现分两个 workflow，因为验证阶段是纯机械的、固定可复用：

### 1. `superpowers-verify` (纯验证，先做这个)

最机械、最固定的部分——编译检查 + 运行测试 + diff 审查。无交互，可复用。

### 2. `superpowers-implement` (实现编排)

按计划分步派子 agent，每步负责一个独立模块。写完后触发验证。
