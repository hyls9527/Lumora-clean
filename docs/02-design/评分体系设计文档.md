# 评分体系设计文档（夯 → 拉 · 判断层）

> 状态：方向已确认，设计稿待实施
> 原则依据：CORE-PRINCIPLE.md —— 只服务 AI 生图创作者；AI 是主语；禁止普通图库功能形态。

## 0. 一句话定位

评分不是功能，是 AI 的判断层。内部严格结构化，外部只以「夯 / 稳 / 拉」出现在 AI 的决策与解释里；界面上不新增任何评分控件。

## 1. 产品语言：三档

| 档位 | 含义 | AI 的对应动作 |
|---|---|---|
| 夯 | 值得留的作品 | 样张候选、优先复用、优先展示 |
| 稳 | 能用但有短板 | 备选、可进对比 / 精修建议 |
| 拉 | 翻车了 | 回收建议、重 roll 提示 |
| 未评分 | 模型不可用或尚未计算 | 不冒充，不参与策展 |

内部保留 0-10 连续分；档位映射规则只在 Rust 侧实现一份，前后端不各自定义，避免口径漂移。

## 2. 引擎：真实且严格

- 分档引擎（绝对 0-10）：improved-aesthetic-predictor（Apache-2.0）——CLIP ViT-L/14 + MLP 输出 1-10 绝对美学分，直接决定夯 / 稳 / 拉。
- 偏好引擎（相对）：HPS v2（Apache-2.0）——输出原始偏好 logit（无绝对 0-10 语义），只有同一 prompt 下比较才有意义；存储原始分，供同 prompt 变体对比与库内百分位解释。
- 个性化（后续阶段）：用创作者自己的梅花印反馈校准阈值与权重——全局基线是起点，个人审美是终点。
- 可复现：每次评分记录模型版本（scoring_model）与时间（scored_at）。
- 可解释：风格类别 + 库内同类百分位（如“在 Animation 类里超过 87% 的图”），供 AI 回答「为什么这张图是夯 / 拉」；维度明细（构图 / 光影 / 手部 / 文字）留作后续可选增强，不承诺做不到的输出。
- 许可证：主包只内置 Apache-2.0 模型；AGPL 模型（aesthetic-predictor-v2-5）不内置。

## 3. 判断层落在现有功能上（不新增评分形态）

- 导入 / 生成后后台自动评分，不阻塞主流程。
- 智能收藏：新增 `score` 规则字段（夯 / 稳 / 拉），与现有 `rating` / `model` / `prompt` 规则并列。
- AI 控制层：新增意图——「这批最夯的是哪张」「哪些拉了」「把拉的移到回收站」「建相册 夯」。
- 自动策展：仪表盘或回收建议中，AI 批量给出「拉」的建议，创作者一句话确认，而不是挨个看图找角标。
- 解释：问「为什么这张图在这里」，AI 引用风格类别与百分位回答；这是评分唯一被说出来的地方。
- 明确不做：评分条、评分筛选控件、评分排序、卡片分数角标——这些是普通图库形态。

## 4. 第一步实施范围（一次只做这一口）

1. DB：`images` 表新增 `hps_score` / `hps_style` / `aesthetic_score` / `scoring_model` / `scored_at` / `score_label`（三档）。
2. Sidecar：`aesthetic_server.py`——aesthetic 0-10 分档（缺失则「未评分」）；HPS v2 作为同 prompt 偏好分（可选）。
3. Rust：`score_image_cmd`（沿用 `clip.rs` 模式）+ 三档映射 + 持久化。
4. 智能收藏：规则字段支持 `score`；AI 控制层注册相关意图。
5. 测试：档位映射、降级路径、智能收藏规则、AI 意图解析。
6. 不做：个人校准、AGPL 集成、任何评分 UI。

## 5. 验收标准

1. 图片导入后自动产生「夯 / 稳 / 拉 / 未评分」，不阻塞浏览。
2. 同一张图 + 同一模型版本，重复评分结果一致。
3. 档位映射规则只有 Rust 一份实现。
4. 模型不可用时明确显示「未评分」，不抛错、不假评分。
5. 主包不含 AGPL 依赖。
6. 代码审查确认：未新增任何评分控件。
7. 前端测试、Rust 测试保持全绿。
