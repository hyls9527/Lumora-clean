# Lumora 深度审计缺陷清单（t1）

- 审计人：auditor（lumora-fix-team）
- 日期：2026-09-04
- 范围：Lumora 全仓库（前端 `src/**`、Rust `src-tauri/**`、Python sidecar、E2E、CI/发布脚本）
- 方法：只读静态审计（审计员亲验 + 3 个并行子代理：前端 / Rust / CI·E2E·sidecar）+ 全量质量门禁本地实测（Windows 本机）。证据日志：`.audit-logs/*.log`。

## 三、P1 详情（必须闭环）

### C-1 E2E 首启弹窗阻塞（P1）
- **现象/复现**：`npx playwright test` 3/5 失败，日志：`<div role="dialog" aria-modal="true" aria-label="欢迎使用 Lumora">…</div> intercepts pointer events`（重试 103 次直至 60s 超时）。`test-results/core-*.png` 可见全屏遮罩。
- **根因链**：① `playwright.config.ts` webServer 仅 `npm run dev`（浏览器模式，无 `__TAURI_INTERNALS__`）→ ② `src/lib/tauri.ts` mockResponse（56-121 行）**无 `get_setting` 分支**，兜底返回 `null`（120 行）→ ③ `src/App.tsx:78-100` 将 `store_mode===null` 判定为"首次启动"，600ms 后 `setFirstRunOpen(true)` → ④ `FirstRunModal.tsx:19-32` 全屏 `inset:0; z-index:100000` 遮罩，无关闭途径 → ⑤ `tests/e2e/core.spec.ts:16-24` `openCleanApp` 只清 localStorage 并等待标题可见（被遮挡元素 `toBeVisible` 仍通过），**从不关闭弹窗/预置 store_mode** → ⑥ 所有点击类测试必然被拦截；纯可见性断言测试 1 侥幸通过。
- **影响**：E2E 对首启弹窗零防护；Dev 模式每次刷新都弹窗（无持久化）。
- **修复建议**（a+b 组合）：a) mockResponse 为 `get_setting` 增加持久语义（`store_mode` 返回 `'reference'`）；b) `openCleanApp` 显式等待并点击弹窗「保持原位置」后断言弹窗消失（`expect(dialog).toBeHidden()`），并新增一例"首启弹窗出现→选择→不再出现"。
- **关联测试**：`core.spec.ts:38,69,87`。

### C-2 cargo fmt 门禁失败（P1）
- **现象**：`cargo fmt --check` exit 1；CI `ci.yml:103-105` 已含该步骤 → main 上 Rust job 必红。
- **根因**：`import.rs:129,138,1094`、`ops.rs:910,917,925,932`、`smart_collections.rs:183,213` 提交前未跑 fmt。
- **修复**：`cargo fmt` 后提交即可，不改 CI。注意 release.yml 无 fmt（C-6），格式化缺陷可绕过 PR 门禁发布，建议顺修 C-6。

### R-1 备份导入破坏活动数据库（P1）
- **根因**：`commands/backup.rs:56-80`：`fs::copy(staging, db_path)` 覆盖**仍在使用的** DbHandle 连接主文件，随后删除 `-wal/-shm/-journal`；不关连接、不校验目标 schema、非原子。SQLite 旧连接的后续写会重放旧 WAL；Windows 上拷贝/删除还可能共享冲突。
- **影响**：导入的库被旧数据污染/损坏；导入与重启之间的任何写入都落在"新文件+旧连接"上。
- **修复**：用 SQLite Online Backup API（rusqlite `backup`）在活动连接内安全导入；或写入 pending-import 标记、重启时替换；至少"关连接→rename→重开连接 + integrity_check"。补"导入后活动连接仍可读写"回归测试。

### R-2 已 CLIP 嵌入图片永久删除必失败（P1）
- **根因**：`trash.rs:65-97 permanent_delete_tx` 未删 v9 的 `clip_embeddings`/`vec_embeddings_clip`；`clip_embeddings.image_id REFERENCES images(id)`（schema.rs:163-169）+ `PRAGMA foreign_keys=ON`（db/mod.rs）。
- **影响**：任何有 CLIP 嵌入的图片，`permanent_delete_image` / `empty_trash` / `batch_permanent_delete` 全部报 FK 错误 → **回收站永远清不空**。
- **修复**：images 删除前追加 `DELETE FROM vec_embeddings_clip WHERE image_id=?1; DELETE FROM clip_embeddings WHERE image_id=?1;`
- **关联测试**：`trash.rs permanent_delete_cascades` 应补 CLIP 行断言。

### R-3 MCP/LAN 任意路径导入与读取（P1）
- **根因**：① MCP `import_images(path)`（mcp.rs:146-155 → `import_folder_gated`）无目录白名单/用户确认；② `image_file_impl`（mcp.rs:436-499）对解码失败文件回退原始字节（≤20MiB），LAN `/api/images/{id}/file`（lan_server.rs:305-352）同类回退**无上限**。
- **影响**：持有 token 的 AI 客户端可导入机器上任意 `*.png/.jpg` 命名文件并读回内容；LAN 端超大文件可 OOM。
- **修复**：`image_file_impl` 与 LAN handler 一律走 `validate_image_access`（ops.rs:17）；LAN 也加 20MiB 上限；MCP import 限用户授权根目录。
- **关联测试**：伪造 `foo.png`（任意字节）注册后读取应被拒/限尺寸；LAN >20MiB 应 413。

### R-4 畸形 PNG iTXt 越界 panic（P1）
- **根因**：`metadata/png.rs:66-67` 守卫 `null1+2 > data.len()` 通过后仍 `&data[null1+3..]`；当 `null1+2 == data.len()` 时越界 panic。
- **修复**：`if null1 + 3 > data.len() { return None; }`；两个尾部 null 字段同样加边界检查。
- **关联测试**：feed `b"key\0\0"`、`b"key\0"` 断言 None 而非 panic。

### F-1 语义搜索从不渲染结果（P1，核心功能）
- **现象**：语义模式下输入关键词按回车，结果区永远空白或显示旧精确搜索结果。
- **根因**：`SemanticSearchBar.tsx:62` 调 `search()` → 写入 `semanticSearchStore.results`（semanticSearchStore.ts:66）；但 `SearchPage.tsx:77-79` 的结果只来自 `imageStore.getSearchResults()`（**对当前图库页内存过滤**，imageStore.ts:289-295）与 `imageSearchStore.results`——**全仓无任何组件消费 `semanticSearchStore.results`**（App.tsx/SearchPage 只取 `mode`）。
- **影响**：语义搜索（旗舰功能）在 UI 上不可见，用户以为搜索坏了。
- **修复**：SearchPage 在 `searchMode==='semantic'` 时渲染 `semanticSearchStore.results`（映射为 ImageRecord）；或让语义搜索复用 imageStore 结果管道；删除死字段。
- **关联测试**：`SearchPage.test.tsx` 只断言提示文案，从不渲染结果（假通过）。

### F-2 嵌入补齐无限循环（P1）
- **根因**：`embeddingStore.ts:136-144/156-164` `for(;;)` 仅 `remaining<=0` 终止；后端 `embed_missing` 返回 `{processed:0, remaining:N}`（图片嵌入静默失败仍计 pending）时永不退出；无取消按钮。对比 `aesthetic.ts scoreBackfill` 已有 `processed===0` 守卫——此处遗漏。
- **修复**：两处循环加 `if (result.processed === 0) break;`（并显示错误信息）。
- **关联测试**：`embeddingStore.test.ts:146-169` 只测递减 remaining，无 processed=0 停滞用例。

### F-3 生产环境静默回退 mock（P1）
- **根因**：`tauri.ts:215-253` 若 `isTauri` 但 `import('@tauri-apps/api/core')` 失败一次，`_realInvoke=null` 后**无条件**走 mockResponse：列表返回空、写命令返回 undefined 且通知 writeListeners → 用户看到"数据全没了"且操作"成功"。
- **修复**：`isTauri && !_realInvoke` 时抛错（fail visibly），mock 仅服务 `!isTauri`。
- **关联测试**：`tauri.test.ts:30-39` 只测成功路径。

### F-4 以图搜图结果大部分消失（P1）
- **根因**：`SearchPage.tsx:508-511` SearchResultCard 用 `useImageStore.getState().getFilteredImages().find(...)`——只查当前加载的图库页（≤40 条）；getState() 还非响应式。
- **修复**：按 id 从后端取完整 ImageRecord（或维护 id→record 全局映射并随所有列表响应填充），渲染结果载荷自身。
- **关联测试**：SearchPage.test 无以图搜图用例。
