# 迭代轮 3 — 性能表现（2026-08-02）

## 1. 迭代目标

优化响应速度与资源利用率，验证高负载（10K 级图片库）下的稳定性；确保构建产物与运行时路径均处于预算内。

## 2. 实测基线（优化前/测量）

| 指标 | 实测值 | 说明 |
|------|--------|------|
| 批量插入（Rust） | 1000 张 / **101ms** | `bulk_insert_1000_images_performance` |
| 分页查询（Rust） | 1000 张中查 40 条 / **310µs** | 同测试 |
| 前端主 chunk | 266KB（gzip 84KB） | 页面全部懒加载 |
| 构建产物 | 0.4MB / 预算 0.5MB | perf-budget |
| 前端全量测试 | ~38s / 659 用例 | vitest |

## 3. 优化项

| # | 优化 | 收益 | 验证 |
|---|------|------|------|
| PERF-1 | `list_images_filtered` 日期下界从 `date(created_at) >= ?` 改为 `created_at >= ?` | ISO 字典序可直接比较，**created_at 索引可用**（此前函数包裹导致全表扫描） | 既有筛选测试全过 |
| PERF-2 | 日期上界改为半开区间 `created_at < date(?1, '+1 day')` | 保持「结束日整天含入」语义，同时右侧为常量，`<` 比较仍可走索引 | `filtered_list_date_to_includes_entire_day` 通过 |

## 4. 既有性能机制确认（无需改动）

- `LazyLoad`：IntersectionObserver 双向挂载/卸载，DOM 节点上限约 3 个视口高度（10K 图片场景）。
- `InfiniteScroll`：IntersectionObserver 哨兵，靠近底部才加载下一页。
- `usePerformanceMonitor`：关键组件渲染耗时监控（App/Sidebar/DetailModal 等）。
- 语义搜索：LRU 缓存（30min TTL / 5MB 上限）+ 防抖。
- 后端：`bulk_insert` 1000 张仅 101ms，单库连接 + WAL，无并发锁竞争热点。
